# 本机网页自动化与参数化流程设计

日期：2026-10-26；状态：用户已确认，按最小闭环分阶段实施；当前交付范围见实施计划和 README。

## 1. 目标与已确认需求

构建本机单用户应用：用户在 Web 页面输入自然语言，Agent 操作独立浏览器，旁边显示实时画面。首次执行成功后，将操作转换为带参数的可复用流程。后续通过参数表单替换产品名称等值，正常执行无需调用 LLM；执行失败时允许自动调用 LLM 修复。

已确认：浏览器操作统一使用 vercel-labs/agent-browser；自行开发应用与流程引擎，借鉴 Workflow Use 思路；支持自动登录、顺序操作、查询、有数据继续/无数据结束、文件导出到指定本机目录；自动识别参数后由用户确认；可配置 OpenAI 兼容 API 地址、密钥与模型；本地变更提交并推送至 https://github.com/Sora-Ava/agent_browser_workflow 。

以下技术默认值由设计者提出，用户可在审阅时调整，不能视为已经逐项确认。

## 2. 方案取舍

已选择：自建 TypeScript 应用，agent-browser 负责浏览器控制，自建参数、录制、分支和回放逻辑。可独立演进，不复制 Workflow Use 源码。

未选择：改造 Workflow Use，虽然能复用部分模型和 UI，但需替换执行层，并处理 AGPL-3.0 许可证约束。

不采用每次全程使用 Agent 的方案，因为它无法满足正常回放不调用 LLM 的核心目标。

## 3. 首版边界

优先支持 Windows 本机 Chrome/Chromium，服务仅监听回环地址。一次只执行一个任务；浏览器由应用独立管理。没有多用户、远程部署、定时任务、批量任务、任意循环、通用可视化流程编辑器或人工示范录制。

支持有限条件分支，不只支持一条线性路径。查询无数据属于正常业务结束，不进入 AI 修复。复杂验证码/多因素认证暂停等待人工完成，不尝试绕过。

首版输出为运行摘要、可配置的确定性文本/表格提取、截图及下载文件列表；JSON 是提取数据的序列化形式，不保证任意网页都能自动提取结构化数据。

## 4. 技术组成

- React + TypeScript + Vite 前端；Node.js + TypeScript 后端；SQLite 保存流程、不可变版本、运行及步骤事件。
- agent-browser 适配器：使用结构化命令参数调用 CLI/daemon，通过 JSON 获取结果。不调用 Playwright API，不拼接执行任意 shell 命令。
- LLM 网关：后端实现 OpenAI 兼容 Chat Completions 调用；工具循环由本应用管理，不依赖 agent-browser 自带 chat 的模型网关。优先使用文本可访问性快照，图像输入为可选能力。
- 回放引擎与探索 Agent 分开：前者只解释受支持流程指令；后者只通过同一浏览器适配器操作并记录动作。
- 画面服务优先转发 agent-browser 的实时帧流到前端；版本不支持时退化为执行步骤后的截图刷新，界面清晰标注模式。

agent-browser 版本固定。实施初期先核验该版本的 Windows 启动、JSON、流协议、下载完成事件、会话持久化、语义定位和输入能力；README 描述不作为已通过测试的证明。若下载或画面接口不满足，需要在写业务实现前记录兼容方案，不暗中引入 Playwright 替代。

## 5. 界面与用户流程

用户指定：Web 界面设计使用 frontend-design 技能。实施前先形成配色、字体、布局和设计原则组成的简短视觉方案，对照本产品用途复核，再实现并通过截图检查。视觉以可观察、可控制的自动化工作台为中心，浏览器画面为主要内容；操作步骤和参数提供清晰层级。具体配色与字体尚未确认，不将技能示例视为用户偏好。支持键盘焦点、减少动态效果和窄屏布局，状态不能只靠颜色区分。

主界面左侧输入指令、查看步骤与消息，右侧实时浏览器画面；支持运行、暂停、继续、停止及人工接管。暂停在当前命令结束后生效，停止取消后续调度和模型请求，不保证撤销已经发生的网页操作。

独立浏览器同时有本机可见窗口，作为人工登录、验证码及接管的可靠入口。首版实时画面以观察为主，不以实现完整远程桌面为前提。人工接管后重新获取页面状态，不能使用旧引用继续盲目执行。

页面还包括：流程列表、参数确认/运行表单、只读步骤及分支查看、版本选择、运行历史、站点凭据管理和模型设置。新增流程须提供起始 URL，可与自然语言一起输入。调用 LLM 的运行显示原因及修复次数。

首次任务：输入 URL 和自然语言 → 选择/新增站点凭据 → Agent 执行并记录 → 成功后生成流程草稿与参数 → 用户调整、确认 → 保存版本。

复用：选择流程与版本 → 填写参数、凭据及下载目录 → 校验 → 检查登录 → 确定性执行 → 展示结果，异常才进入修复。

## 6. 流程表示与参数

流程用经过 schema 验证的 JSON 保存，字段包括 schemaVersion、workflowId、version、startUrl、parameters、credentialSlots、steps、startStepId、successConditions。SQLite 为权威存储；导出 JSON 不含真实凭据。

步骤包含稳定 ID、动作类型、目标定位、参数绑定、前置/后置条件、超时、成功后的 nextStepId；条件步骤额外包含规则及 true/false 目标。保存前校验引用、参数类型、可达性和无环性。首版不允许任意 JavaScript 或模型生成代码直接执行。

动作集合：navigate、click、fill、select、press、wait、assert、condition、extract、download、finish。动作和查询结果校验都由代码执行。

定位保存角色+可访问名称、label、placeholder、test-id 或 CSS 等明确定位方式；同一步可有按优先级排列的候选。定位到多个元素时不任意点击。快照中的 @eN 只用于当前探索，不能成为跨运行定位依据。需保存 frame 和 tab 上下文；首版支持单业务标签页和导出引起的新标签页，未实现的 frame 场景应明确报错。

参数类型首版为 string、number、boolean、date、enum、directory，支持必填、默认值及基础约束。每个参数显式绑定一个或多个字段；文字常量保持常量。账号密码使用 credential 引用，不混入普通参数默认值、动作日志或流程 JSON。参数按结构化值传入，不当作 shell、选择器或代码直接插值。

首次只走过一个分支时，不能声称另一分支已验证。系统可生成另一分支的规则草稿并标记未验证；用户确认规则后允许保存，但界面持续显示验证状态，直到实际覆盖。

## 7. 登录与本地配置

凭据以站点 origin（scheme、host、port）和用户自定义账号别名组织，一站可有多账号。SSO 的不同 origin 单独关联，密码只填入明确配置的登录 origin。流程选择凭据引用；后端执行前才读取真实值。

第一版允许本地明文 data/credentials.json，模型配置放 data/settings.json；.env 可作为初始配置来源。Web 修改写入本地设置，不回显完整密钥。日志脱敏，流程录制保存引用；页面快照或截图可能包含账号或业务数据，应留在本地并在发送模型前尽量移除敏感输入值，不承诺绝对不泄露页面渲染内容。

浏览器使用独立持久化 profile；保存可确定判断的已登录状态条件，已登录则跳过登录子流程，失效则重新登录。若未能区分登录页与页面故障，停止盲目填充并进入修复。验证码进入 waiting_for_user，用户完成后重新检查登录成功条件。

## 8. 查询分支

流程必须先等待查询完成的明确条件，例如 loading 消失且结果区域进入完成状态；不能用固定 sleep 或暂时零行直接推断无数据。

随后判断：明确的空状态文字/标志 → finish(no_data)，提示“未查询到数据”；有效结果行存在 → 下一步。两者都不满足或同时满足视为状态不明，超时后修复。后置条件与规则在首次生成后可供用户检查。

## 9. 下载

支持全局默认目录、流程默认目录和运行覆盖值，运行值优先。校验本机绝对目录、写权限，必要时创建目录。每次下载先保存到本次运行临时目录，确认浏览器下载完成后再安全移动到目标目录；过滤服务端文件名中的路径字符，重名添加时间戳与唯一后缀，不覆盖。

记录下载 ID、发起步骤、源文件名、最终路径、大小及状态；超时保留诊断信息且不宣称导出成功。确认已有下载完成则不重新点击导出；触发状态不明时检查下载记录，无法确定则等待人工决定。页面出现下载链接不等于下载成功。

## 10. AI 修复与版本

状态机：queued → exploring/replaying → repairing 或 waiting_for_user → succeeded/no_data/failed/cancelled。浏览器动作串行；界面断开不启动第二个任务，重新连接可查看原运行。

默认每次运行最多两次修复，每次最多十个工具动作，普通动作默认超时 30 秒、下载 120 秒，均为设计默认值。模型请求也有超时与工具预算，避免无限循环。

失败时保存当前 URL、脱敏快照、失败步骤、最近结果和执行账本。LLM 只能返回受支持动作/定位或分支规则修改，不得自行改变用户目标、输出目录或凭据 origin。页面文本是任务数据，不是系统指令。

修复先检查后置条件：已完成则向后推进；可确认未发生的只读或幂等操作可重试。提交、删除、保存、付款等结果不明的有副作用操作不得盲目重放，进入人工确认；下载以专门记录去重。正常权限与模型权限相同。

修复后成功完成当前运行才产生新版本；失败不覆盖原流程。保留旧版本和修复差异；新版本可成为下次默认版本，但未覆盖的分支继续标记未验证。若用户改动业务目标，应新建或手动另存流程，不自动当作修复。

## 11. 本地文件与源码管理

data/ 下存数据库、设置、凭据、profile、运行截图及临时下载，全部忽略；downloads/、.env 及其本地变体也忽略，仅提交不含真实值的 .env.example。目录权限沿用本机用户，不在首版引入复杂加密或权限系统。

源码、测试、设计及使用文档提交到指定仓库；提交前检查暂存内容不含真实密钥、账号、站点数据和运行产物。公开仓库中的演示仅使用虚构站点及数据。

## 12. 验收

使用本地测试网站验证真实 agent-browser，不只 mock：

1. 自然语言完成首次登录、查询产品 A、导出，画面与步骤状态可观察。
2. 系统提出 product_name 参数，用户确认后保存；参数 B 运行时使用同一流程，LLM 调用计数为零，文件下载到指定目录。
3. 模拟无数据，等待查询完成后以 no_data 正常结束，无下载、无 AI 修复。
4. 清除会话后自动登录；保持会话时跳过登录；验证码暂停接管后继续。
5. 改变定位触发 AI 修复，恢复后生成新版本；修复超预算停止。
6. 下载延迟、失败、重名及触发结果不明均得到正确状态，不重复导出或覆盖文件。
7. 暂停/取消、刷新界面、服务重启不会无意重启或重放任务；重启时将未完成运行标记 interrupted，人工重新发起，不自动续跑。
8. 流程导出与 Git 暂存内容不含凭据；普通回放不构造模型请求。

断网零 LLM 验收使用本机测试站点并禁用模型接口；真实内网站点仍保留必要网络连接。
