# 行迹 · 本机浏览器工作台

使用自然语言操作独立浏览器，成功后确认可变参数并保存流程。重复运行使用确定性步骤，正常回放不调用 LLM。

本项目使用 **agent-browser 0.39.2** 控制浏览器，不使用 Playwright API。

## 启动

需要 Node.js **24+**、npm 和 Chrome。已在 Windows + 本机 Chrome 上验证。

```powershell
npm install
npm run build
npm start
```

打开 [本机工作台](http://127.0.0.1:3001)。开发模式运行 `npm run dev`，打开 [开发界面](http://127.0.0.1:5173)。不要把服务暴露到公网。

若本机 Chrome 未自动找到，可设置环境变量 `BROWSER_EXECUTABLE` 为浏览器完整路径，或运行 `npx agent-browser install` 安装 Chrome。默认启动可见的独立浏览器；设置 `BROWSER_HEADED=false` 可无头运行。

## 从演示开始（无需模型）

1. 在操作台点击“先试试本机产品查询演示”，加载预置流程。它是演示模板，不是模型生成结果。
2. 在“模型与站点设置”里保存站点账号：网址 `http://127.0.0.1:3001`，任意别名，账号 `demo`，密码 `demo123`。
3. 返回操作台，选择保存的账号，填写“产品 A”或“产品 B”，点击运行流程。
4. 浏览器自动登录、查询、读取结果并导出 `products.csv` 到项目 `downloads` 目录；重复下载会加后缀，不覆盖文件。
5. 将产品名改为“不存在的产品”，会显示“未查询到数据”，正常结束且不下载。

无需为演示填写模型设置；演示模板和正常流程回放不会请求模型。

## 自然语言操作

在设置中填写 OpenAI 兼容 API 地址（通常以 `/v1` 结尾）、密钥和支持工具调用的模型名称。密钥留空会保留已保存值；无需密钥的本机模型也可使用。

回到操作台新建任务，输入目标网址及明确目标。例如：

> 登录产品系统，查找产品 A。等待查询完成，无数据就结束；有数据则读取结果并导出 CSV。

首次由模型决定动作，通过同一浏览器适配器执行和录制；完成后显示参数草稿，修改显示名称/默认值，再保存。保存后的流程通过参数表单运行。密码通过选定的凭据引用注入，不需要在自然语言中填写。

接口连接和工具循环已有本地脚本模型合约测试，但**未使用真实付费模型评估自然语言理解成功率**。实际效果取决于所配置模型和目标页面。

## 当前版本的范围

已实现：

- React 中文工作台、模型设置、站点凭据、流程列表与本机运行记录。
- 独立持久化浏览器、自动登录、已登录时跳过、顺序动作、明确加载标志等待。
- 查询空结果正常结束、有结果继续；确定性文本提取；下载到本机目录。
- 探索动作录制、自动提出字符串参数、确认保存到 SQLite、替换参数零模型回放。
- 任务互斥、暂停/继续、停止后续调度、重启不自动重跑与错误记录。
- agent-browser 原生连续实时画面，连接不可用时回退至步骤快照；暂停期间画面继续更新。
- 定位失效时自动调用模型修复，最多两轮；成功后保留原流程并生成新版本，界面可切换版本。

后续增量：

- 更复杂的失败恢复、版本差异编辑、多种参数类型、任意分支及分页循环。
- 验证码自动识别和更完整的人工接管引导；目前可暂停后在独立浏览器中处理，再继续。
- 凭据编辑/删除、模型连接测试、流程编辑/导出、更完善的跨标签与 iframe 支持。

当前查询分支是明确的“无数据结束 / 有数据继续”，不是通用分支编辑器。参数 UI 可改显示名称和默认值；绑定由首次记录生成，不能在 UI 任意重连步骤。暂停和停止在当前浏览器命令结束后生效，不撤销已发生的操作。继续前会重新读取页面状态。

自动修复只修改当前步骤的稳定定位，不能改变动作类型、输入参数、账号或目标 URL。定位在动作发出前无法匹配，或只读等待/提取失败时，可尝试修复；已发出的点击、登录提交或下载结果不明时会停止，不自动重试。正常回放仍不调用模型。修复成功且本次任务完成后才保存新版本；旧版始终保留。尚未提供通用的任意步骤重规划。

## 本地数据

- `data/settings.json`：模型连接与默认下载目录，密钥仅保存在本机。
- `data/credentials.json`：按 origin 和账号别名保存明文凭据。
- `data/workflows.sqlite`：流程与运行事件。
- `data/profile`：独立浏览器 profile。
- `data/pending`：每次下载独立临时子目录；失败残留供排查。

以上数据、截图、`.env` 和下载目录均被 Git 忽略。第一版没有本地静态加密。现有数据库会自动补齐版本元数据；原有流程作为版本 1，修复成功后生成版本 2 及后续版本，不覆盖原步骤。

Windows 的 agent-browser 原生下载路径规范化存在兼容问题，本项目仅下载策略/完成事件使用该浏览器提供的 CDP 地址，并传入原生反斜杠目录。页面点击仍经 agent-browser。下载必须收到完成事件且文件实际存在后，才移动到用户目录。

## 验证

```powershell
npm test
npm run build
npm run test:browser
npm run test:control
npm audit
```

`test:browser` 启动临时本机测试站点和真实 Chrome，验证自动登录、会话复用、参数 A/B、零模型回放、无数据结束、实际文件内容及重名不覆盖，还使用脚本模型验证探索录制接口。测试创建的 profile 和文件在结束后清理，不使用真实账号。

`test:control` 验证无步骤执行时和暂停期间持续收到 JPEG 帧、命令边界暂停/继续，以及脚本模型修复真实页面定位后保存新版本、下一次零模型回放。修复模型也是受控合约服务，不使用用户的真实密钥。
